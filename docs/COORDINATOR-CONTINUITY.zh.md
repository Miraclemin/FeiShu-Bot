# 组织者任务连续性

## 对话入口

- “做到哪了”“有什么卡点”：只查询，不创建任务或文档，不改变任务状态。
- “继续做”：沿用当前未结束的任务和文档；目标不明确时询问任务编号。
- 回复原任务消息或注明 TEAM 编号，优先关联该任务；不同群、话题仍隔离。
- “暂停”或 `/team pause`：停止后续派单，继续保存已发任务的回执，不强停执行进程。
- `/team resume`：核对原任务后继续，不自动重复发送状态不明的派单。
- 取消、已完成任务不会被一句“继续”复活。新目标加入群进度文档，保留独立任务编号和执行上下文。
- 分流采用保守规则；未识别为执行目标的普通对话不自动创建任务。当前仍保持每个群/话题一个未结束的协作任务。

## 接手和验收

1. 外部执行先安排 `kind: preflight`，只读检查该任务所需目录、技能、工具和凭证是否可用；不得输出密钥或试扣费。
2. `kind: work` 引用同执行者已完成的 `preflight` 步骤。检查未通过不得开始工作。
3. 独立检查使用 `kind: review` 和 `verifies: [工作步骤编号]`；执行结果未通过独立检查不得完成任务。
4. 待补充、失败返工使用 `resumes` 引用原步骤。相同任务的执行者会话可继续，不同任务隔离。已有的外部 Codex 会话不会自动迁移；需要核对原环境。
5. 人的新反馈、暂停和取消优先于旧模型轮次的结果。

## 群消息和任务文档

- 不再连续发送登记、处理中、文档创建三条提示。
- 群内派单只包含执行者、步骤类型和任务链接。完整指令先写入原任务文档，接收 Bot 读取并校验摘要与收件人。
- 文档不可读、指令被更改或同步失败，返回阻塞，不靠猜测执行。
- 此协议需要参与 Bot 使用支持该协议的版本；保留读取旧格式完整派单的兼容能力。
- 汇总优先简短，长摘要留在文档。回执及用户反馈继续归档。文档记录结构化过程，不代表完整的底层工具日志。

这些检查保证派单与状态流程，不代替执行工具自己的权限检查或供应商凭证验证。凭证是否真正可用由对应 Bot 的只读检查结果报告，不能因选了 Skill 或目录存在就显示全部准备完毕。

## 群进度文档

同一台机器上，同一组织者在同一个群（包括不同话题）共用一份进度文档。
顶部汇总所有本地登记的任务，下方按任务编号记录详细过程；每次同步把最新总览置顶，旧版本保留。
新任务不会重新建文档；不同群、不同组织者配置各自隔离。旧的独立任务文档不会删除。
当前自动创建文档，不提供手动绑定已有文档和自动按月归档；跨机器的不同组织者也不会自动合并。

测试：在无未完成任务的测试群，先发 `/team start 整理一个三条的会议准备清单`；完成或 `/team cancel` 后，发 `/team start 整理一个三条的会后复盘清单`。
核对两次给出的文档链接相同、总览有两个不同任务编号；问“做到哪了”不会增加任务；另一测试群应得到另一份文档。
