# 飞书共享手册驱动的组织者（试用）

在工作台打开机器人、选择群，填写“组织者协作手册”的飞书 docx 链接后保存。每次群任务开始前，Bridge 使用该机器人的身份读取最新正文；读不到就停止这次任务。流程可以直接在飞书中编辑，无需分发组织者 Skill。

选择“组织者”角色并保存时，没有链接会尝试创建默认手册并赋予机器人的已核验拥有者编辑权限。也可以点“创建或找回本群协作手册”。创建回执保存在配置根目录的 coordinator-handbooks，重试复用文档。文档创建成功但分享失败时，按错误里的链接与权限提示处理，不重复创建。

需要的权限包含文档读取、创建、编辑，以及 `docs:permission.member:create`。统一权限入口已包含这项。手册内容不授予新权限，也不能替代负责人身份验证。

## 开始一次演练

在同一个群中，为双方打开“接收本机已绑定机器人的群内交接”，保存。对组织者说：

> 组织处理一次演练：让测试检查这条记录的复现步骤是否清楚，给出一条建议。你收到结果后汇总。本次不改代码、不上线。记录：……

每条交接应带任务编号、目标、证据、验收标准和回复对象。只以真实“已接单”和结果消息推进，发送成功不代表完成。需求、Bug和巡检记录继续沿用群中绑定的表。

## 当前实现边界

- 工作流是文档指导下的 Agent 执行，不是完整的事务工作流引擎。
- 交接接收每10秒检查已开启群最近50条消息，只处理本机同时绑定该群且开启交接的其他应用发出的真实定向 @。普通人的消息仍走原来的实时通道。
- 本机其他机器人是通过应用 ID 识别，不凭显示名称。跨电脑自动交接尚未覆盖。
- 同一进程对消息去重，每群每10分钟最多12次自动交接；超过上限发送提示。重启后不重放启动前的消息，离线交接恢复需人工重发。
- 复杂并发任务、事务锁、审批后自动恢复未在此功能中实现。上线仍需原项目的负责人确认。
- `/stop` 是现有停止入口；停止组织者不会自动终止其它机器人已经开始的工作，需要对对应执行者分别停止。
- 界面中的工作角色和工作目录继续按群保存。现有研发角色也可绑定手册，通过职责说明在用户要求“组织处理”时兼任组织者。

## 独立创建协作团队

首页点「创建协作团队」，填写团队名称、工作目标、本机工作目录。扫码新建独立的组织者应用（也可绑定尚未配置其他群的应用），然后点「创建群和共享手册」。

程序验证机器人拥有者，将拥有者设为新私有群的群主；创建群的机器人自动入群。随后创建协作手册，给拥有者编辑权限、给本群查看权限，绑定工作目录及基础飞书技能，最后启用组织者并在新群发使用说明。群外不会自动开放访问。参与机器人是否能读手册仍需实际验证。

新建群需要 `im:chat:create`；手册共享需要 `docs:permission.member:create`，均在统一权限入口。群或手册已经创建而后续失败时，保留本机回执，再次点击复用已有资源。网络中断导致建群结果不确定时停止自动重试，先核对远端群，防止产生重复群。

邀请产品、研发、测试及其机器人入群后，每个机器人拥有者仍要在自己的工作台绑定这个新群、填写职责、选择资料和技能，并开启群内交接。跨电脑交接尚未验收，不应因为入群就声称已完成互联。

第一句话建议：
> @组织者 检查本群协作准备情况，列出成员职责、资料和权限缺项，先不要开发或上线。

准备就绪后：
> @组织者 组织测试检查这条记录的复现步骤是否完整，再让研发评估可行性。你汇总双方结果和证据。本次不改代码、不上线。

创建入口不会把现有研发机器人改成组织者；此前手动配置的“研发兼任组织者”也不会被静默清除。完成新团队验证后可在旧群配置中自行移除兼任职责。

## 组织者与执行者分工

协作手册和项目经验文档只由本群 `coordinator` 角色配置使用。普通角色的旧绑定保留以便切换角色时恢复，但不再自动读取手册，也不注入经验归档指令。

组织者读取流程，按需把已生效经验片段、来源和版本随任务交付执行者；执行者返回任务编号、结果、证据、卡点与经验建议。组织者统一查重和归档经验，长期规则仍需负责人明确确认。普通角色仍可接受人的直接交办。

这是角色分工与上下文编排，不是文件权限隔离；已有文档权限不因隐藏配置而撤销。经验筛选和归档由 Agent 按协议执行，不宣称为底层强制审批。群内交接仍需双方开启，当前仅支持本机绑定的机器人。
