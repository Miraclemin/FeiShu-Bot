# 两种使用方式

## 独立使用（不需要组织者）

各 Agent 绑定并启用自己的群，直接 @它交办任务。人可以自行分工，也可以明确要求 Agent 用真实 @ 交接。无需创建协作群、无需绑定协作手册。

已有组织者也可以在软件的群设置中关闭「组织者模式」并保存。它会变成普通助手，其他 Agent 不受影响。关闭会暂停协调，不会删除记录，也不会终止已经发出的执行任务。

## 组织者模式

1. 为一个 Agent 选择「组织者」角色，开启本群和「组织者模式」，保存。
2. 让参与的 Agent 加入同一群，并在各自软件设置里启用这个群，填写职责、资料和工作目录。跨电脑使用时，执行端也需要支持协作派单/回执协议的版本。
3. 群里发：

   > @组织者 帮我评审这条需求……研发给方案与工作量，测试给验收设计。你收齐后汇总结论和需要我决定的事项。只读，不改代码、不写表、不上线。

软件登记唯一任务编号；组织者按本次授权决定自己完成或拆分工作。派单由软件真实 @，最终结果由软件自动 @回组织者。普通接单消息不调用组织者模型；结果收齐或出现阻塞才继续。组织者可串联实现与验证，但不能自行扩大用户授权。

最多12轮派发（包含澄清、实现、验收和返工），每轮最多4个不同 Agent。结果收齐且最终汇总成功发送后才完成归档，释放当前协作任务；执行锁随每次 Agent 运行结束释放。归档保留结果和证据，旧回执不会重新激活任务。完成“评审”不代表已经开发、测试或上线。

协作手册、经验文档均为选填；未绑定手册时使用内置流程。已绑定手册读取失败时会报告错误。开启组织者模式后，直接 @提出目标就会登记；简单问题由组织者直接回答，无需分派。关闭后恢复普通对话。

## 看进度和处理异常

- `/team status`：查看当前任务，或最近归档结果，不调用模型。
- `/team resume`：发起人或管理员核对历史回执后继续，不自动重发派单。
- `/team cancel`：取消当前协调并保留结果；不会强停执行者，也不能撤销已经发生的操作。
- `/team resolve S1 人工核对结论`：发起人或管理员确认子任务结果，留下人工核对记录，再继续。只在确实核对过时使用。
- 软件群设置 →「协作任务」：查看结果和状态，或取消任务。

派发后15分钟未收齐回执，会在群里提示发起人核对；这是单次本机超时提醒，不轮询群聊、不调用模型、不自动催办或重派。程序退出时无法发提醒；重新启动对应组织者后恢复计时。关闭组织者模式时不发提醒。

发送超时可能已经送达，软件会保留“发送待核对”，避免自动重发导致重复执行。重启后任务记录仍在；离线期间错过的结果，可用 `/team resume` 主动核对（最多读取任务开始后的500条群消息）。话题群的任务按话题隔离，请在原话题使用命令。

## 数据与边界

任务记录保存在当前软件配置目录的 `team-tasks/` 下；默认桌面版为 `~/.lark-workbench/team-tasks/`，按组织者与会话隔离。记录包含任务文本和执行结果，权限为当前本机用户可读写。

软件保证派发记录、实际发送回执、结果归属和生命周期。Agent 报告“完成”不等于软件验证了业务正确性；需要独立验收时，明确要求组织者安排测试。工具访问权限仍由各 Agent 原有配置控制。旧版手工组织的历史任务不会自动迁移到新账本。

## 多轮示例

只发一次：`@组织者 帮我做一个报名页，完成后安排验收，先不要上线。`

1. 组织者读取本群成员职责，选合适的实现与复核人员。
2. 实现者缺报名字段，返回「需要补充」；组织者请懂业务的成员补齐。
3. 答案返回后，组织者将答案连同原目标交还实现者，继续同一个目标。
4. 实现完成后安排验收；不通过则携带证据返工，再次验收。
5. 必要任务全部完成后汇总结果，保留记录并释放当前目标。

每个拥有者请在软件的「职责与能力边界」写清：负责什么、交付什么、可用资料/工具、不负责什么、哪些操作需要人确认。描述不等于实际授权；缺失时组织者先查询或请拥有者补齐。通用流程内置在软件中，绑定的组织文档用于补充业务规则。

执行不是无限循环：每轮最多4人，总计12轮；遇到无法判断的关键问题会请人处理。人工补充会存入当前目标，不会另起目标。`/team cancel` 取消协调但不撤销已经发生的动作。


## 自动任务文档与取消

自动协作每项 TEAM 任务创建一份飞书文档，创建和访问授权成功后才继续派单。发起人可编辑、本群可查看；不会公开给组织外的人。文档按最新进度在前保留历次记录，包含目标、当前状态、分工、执行回执与证据、人的反馈、过程时间线和下一步。人的补充需 @组织者提交；直接手工修改文档不自动视为任务指令。底层工具日志与本机截图不会自动上传，本地路径也不是同事可访问的证据链接。

文档创建失败时暂停后续协作；同步失败保留本机账本，可通过 `/team status` 查看错误、`/team resume` 重试。创建结果不确定时不自动重建，避免重复。新手册和内置流程均包含这项规则；旧的自定义手册不自动覆盖。

人作为协调者时继续使用明确授权的业务表格，不自动把任务文档写入正式表。

| 命令 | 行为 |
| --- | --- |
| `/team help` 或 `/team` | 查看帮助 |
| `/team start 目标` | 新建任务，也可直接 @组织者提出目标 |
| `/team status` | 查看当前或最近任务、文档链接和同步错误 |
| `/team resume` | 核对回执并继续当前任务，不重复派单 |
| `/team resolve S编号 人工核对结论` | 人工确认某步骤结果，不能代替实际验收 |
| `/team cancel` | 取消协调、保留任务记录与文档；不会强停执行者或回滚已执行操作 |

取消、继续和人工核对限任务发起人或管理员。取消后新建会生成新编号、新文档；组织者会话重置，执行者使用任务和步骤独立会话。旧任务的晚到回执不推进新任务。项目文件、共享资料和已经产生的外部修改不会被取消命令删除。
