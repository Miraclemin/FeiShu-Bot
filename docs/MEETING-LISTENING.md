# 持续听会

开启会议智能体、保存并重启对应 profile，入会后程序持续接收飞书提供的实时逐字稿。
无需口头唤醒。发言只更新记录；会中发送 `@bot 问题` 才调用 Agent 回答。
Agent 回答期间，字幕接收独立继续运行。

## 接收与确认

订阅 `vc.bot.meeting_activity_v1` 接收会中活动；邀请和会议结束分别使用
`vc.bot.meeting_invited_v1`、`vc.bot.meeting_ended_v1`。
程序保留基于游标的轮询兜底；推送正常时每 10 秒补拉，分页积压立即继续拉取。
30 秒没有推送时状态显示为轮询，新的推送到达后恢复推送状态。
静默不一定意味着故障，应检查实际字幕是否增加。

控制台显示累计接收句数、最后字幕时间、当前上下文条数和存档位置。
`/meeting transcript` 查看最近字幕，`/meeting ask 问题` 使用当前上下文问答。

## 本地记录

逐字稿写入对应 profile 目录的 `meeting-transcripts/<会议ID的hex编码>.jsonl`。
每行包含 meetingId、meetingNo、receivedAt、sentenceId、speaker、text 和可用的发言时间。
同一句的修订追加保存；按 sentenceId 取最后一条可还原最终逐字稿。
重新加入同一会议继续追加，不覆盖此前的记录。写盘失败会在控制台明确显示。

“字幕上下文条数”只限制发给 Agent 的最近上下文，不限制本地存档条数。
历史存档暂不自动检索进回答或会后总结；它们仍使用当前滚动上下文。
会议结束、离会时会保留尚在等待防抖定稿的最后几句。

## 使用边界

只能保存机器人实际收到的字幕，不能保证补回入会前或服务端已不提供的内容。
必须保持应用/profile 运行并已入会；退出应用后不会继续听，重启后需重新入会。
字幕由飞书提供，本功能不会另行采集系统麦克风或原始音频。

## 验证

1. 入会后连续发言，确认累计句数与最后字幕时间持续更新。
2. 在 Agent 回答文字问题期间继续发言，确认新字幕仍到达。
3. 超过上下文条数后检查 JSONL，确认开头字幕仍在。
4. 正常结束会议，确认最后一句也已保存。
