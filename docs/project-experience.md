# 项目经验留队（第一版）

本功能复用飞书文档作为共享资料，不建立独立知识库服务。

## 使用

1. 在飞书准备一份《项目约定与决策记录》，使用下方模板。
2. 在工作台中打开机器人，选择项目群，将链接填入“项目经验文档”。点击“勾选经验协作所需技能”，确认 lark-doc、lark-im、lark-shared 已安装并有权读写该文档，再保存。
3. 对同项目的产品、研发、测试机器人绑定同一个链接。不同电脑也使用同一链接；每个机器人仍需要自身的访问权限。不会自动把文档公开给其他群。
4. 在群里提出一次纠正，例如“客户名单不能原样发给外部服务，请先整理为经验草稿，不写文档”。检查草稿的适用范围和原始依据。
5. 负责人引用草稿明确确认具体内容；如机器人无法核实负责人身份，由负责人手动归档。第一版确认是 Agent 行为规则，不是后端权限闸门。
6. 换另一个机器人，提出相关新任务，让它先读取项目经验并报告引用编号。检查是否真正读取、采用了该记录。

读取失败、写入失败、未完成回读验证，都不能算闭环成功。聊天历史里的“记住了”不代表已共享。

## 飞书文档模板

项目：填写项目名称

维护负责人：填写真实负责人；不凭机器人名字推断。

### 生效约定

暂为空。经负责人确认并归档后才在这里追加；不要将示例当作生效规则。

每条记录包含：
- 编号与版本：EXP-001 / v1
- 结论：具体约定
- 适用范围：哪些场景适用，哪些不适用
- 原因与证据：原消息、需求、Bug 或验证结果的链接
- 确认人及确认消息链接
- 确认日期
- 状态：生效 / 已废弃
- 替代关系：如果替代旧约定，写旧记录编号

### 待确认

草稿优先留在群里讨论，本区内容也不自动生效。

### 历史约定

保留废弃记录及原因，不删除。

## 实现范围

已实现：按群保存文档链接，校验链接类型，每次通过 startRunFlow 发起工作台任务时注入读取、草稿、确认、查重与回读协议。没有设置链接的群保持原行为。

这不是文档内容的自动预加载，也不是自动审批服务。实际读写由 Agent 使用 lark-doc 执行。定时入口若未经过 startRunFlow，必须另行传递该绑定，不能假设已覆盖。

尚需真实联调：飞书文档权限、跨机器人读取和回写、负责人身份确认。尚未实现：程序强制审批、跨机器写锁、自动冲突合并。多个 Agent 同时归档时建议由一个维护者串行处理，不能以提示词宣称具备事务保证。
