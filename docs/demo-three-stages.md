# 三层协作演示：小王终于能下班了吗？

同一个任务拍三次，观众才看得出省掉了什么。开场延续原稿：

> 小王先别走，对个需求。小王看个 Bug。小王，这事现在什么进展？
> 代码写快了，怎么还是走不了？因为我还在给大家传话。

## 三层画面

| 层级 | 拍什么 | 实际操作 | 让观众看到的变化 |
| --- | --- | --- | --- |
| 个人 AI | 群聊里三条零散需求，切到研发自己的 AI 对话 | 人整理范围、复制背景，让自己的 Agent 处理 | AI 帮一个人执行，交接仍靠人 |
| 共享表格 + 人带队 | 同一条记录的标题、目标、验收标准；群里两次 @ | 先 @执行者，收到成果后，人把同一记录和成果交给 @复核者 | 背景不用反复解释，但人仍要推动下一步 |
| 组织者接力 | 人只发一条目标，组织者派单、执行者回执、复核、汇总 | @组织者「组织协作：……」，中途用 /team status | 省掉传话、等待、收集和整理；人判断成果是否值得采用 |

第一层的杂乱聊天可以明确标为情景演绎；后两层的回复、时间和结果必须用实际运行录屏。不要把等待剪掉后宣称“瞬间完成”。

## 先用内容创作演练，不动生产代码

同一素材：三个人下班前还在对需求、查 Bug、问进度。目标：一份 180 字以内的口播草稿。

角色设置 →「新增自定义角色」，可以填写：

| 角色 | 可直接复制的职责 | 需要的技能 |
| --- | --- | --- |
| 内容策划 | 根据给定素材提出受众、冲突、三段提纲。区分事实与设想，不编造产品能力。 | 纯文字无额外技能；读选题表时选择 lark-base |
| 内容审校 | 审查收到的提纲，指出夸大、缺依据和表达不清之处，给具体改句。未验证能力明确标注。 | 纯文字无额外技能；读参考文档时选择 lark-doc |
| 组织者 | 按依赖分工，策划完成后才交审校。保留关键意见，汇总待确认稿，收齐结果后结束。 | 使用组织者角色；读取手册时选择 lark-doc |

名称不决定能力。Prompt 定义职责，Skill 提供操作方法，账号/应用权限决定实际能访问什么。lark-shared 是飞书技能的公共依赖；lark-im 只在 Agent 需要主动执行额外消息操作时使用，软件的派单和自动回执不需要 Agent 自己调用消息工具。

用户可替换成“研究 → 分析 → 复核”“销售线索整理 → 方案起草 → 商务审核”等，不需要为每个名称编写新 Skill。组织者必须知道实际成员与分工；不会仅凭机器人名字可靠推断。

## 用户复测步骤

1. 三个机器人加入同一个演示群，各自在工作台绑定并启用本群、选择工作目录，保存并启动。
2. 一个选组织者角色并开启组织者模式；其他两个填自己的职责。已有群也能使用，不强制新建。
3. 手动模式先只 @策划：根据上述素材写 120 字以内的三段提纲。收到后，人引用该结果 @审校。组织者不会自动插手普通提问。
4. 自动模式只 @组织者，发送下方任务。把示例名称换成自己的成员，@组织者要从飞书候选列表选择。

> 组织协作：口播演练。内容策划先围绕“小王下班又被叫住”写 120 字以内三段提纲；收到后把原文交给内容审校，指出一处夸大风险和一条修改建议。最后汇总 180 字以内待确认稿并结束。两个步骤按顺序执行。只用本条背景，不改业务表、不改代码、不发布。

5. 观察：先出现策划派单，再出现真实策划结果，之后才有审校派单；最后由组织者汇总。无需人中途再 @第二位。
6. @组织者 `/team status`：应显示已完成。再发一个新任务，编号应不同，旧回执不会唤醒新任务。
7. 如卡住，先查状态和真实结果，再由发起人使用 `/team resume`；不要重复发送同一业务任务。取消用 `/team cancel`，它取消协调，不会强杀已在执行的任务。

## 第二层如何加表格

用独立演示表，建议字段：编号、目标、背景、验收标准、负责人、状态、成果链接。写一条 DEMO 记录，状态为“待评审”，把该记录链接绑定到参与者的群资料，检查读取权限。

先只授权读取这一条。@策划整理提纲，再由人 @审校；需要写回时明确指定这条记录、字段和值，避免改真实 Bug 表。完成判断来自成果和复核，不能只看状态标签。

## 研发版替换方式

将同一目标替换为一个本地演示项目的小改动，例如“把一直转圈的任务状态改为等待中、执行中、失败并可重试”。执行者交付预览和验证步骤，复核者实际操作并附证据，组织者收齐后请求人确认。开发与验收要用各自可访问的同一版本；只有方案评审不能拍成代码已经实现。

## 当前边界

- 群里明确发起 → 按任务接力，与“表格改成已批准就自动触发”是两件事。后者尚未在这次链路中验证，不能作为已完成功能演示。
- 会议转录 → 自动任务也需要额外验证，本次不包含。
- 跨电脑需要兼容版本、各自可用的技能与资料权限；同机成功不证明跨机成功。
- 最多 3 轮派发、每轮 4 位执行者；不是无限循环。正式发布仍遵循负责人的明确决定。
- 简单任务直接给一个 Agent 更省；组织者适合多个有依赖的交付物。收益应看人工交接次数、漏项和完成质量，不是机器人聊天条数，也不保证更省 Token。
