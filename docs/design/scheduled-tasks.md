# 定时任务产品设计

日期：2026-09-21
状态：首版已实现，下面保留完整设计；实际交付范围以本节为准。

## 当前实现范围

- 首页统一管理计划，支持一次、每天、周一至周五、每周和时区；预览确认后启用。
- 同一 Agent 支持多个群／Topic 计划；Topic 计划从话题内 @机器人创建。群内支持明确格式的每天、工作日、每周时间，默认北京时间。
- 支持确认卡、命令、暂停、恢复、编辑、删除、立即运行、执行记录、结束本次并暂停。
- 每次实际启动创建独立任务文档；支持单 Agent 和组织者模式。等待人工时暂停，同群／Topic 忙时跳过。
- 电脑联网、未休眠且软件与机器人运行时触发；超过两分钟的迟到或启动时错过的计划不补跑。
- 暂未实现离线保存表单草稿、仅记录不通知、节假日调休、任意自然语言时间、按 Agent 筛选和专用超时配置。
- 同一条消息和同一张确认卡幂等；另发相同内容需再次确认才会建立新计划。
- 自动化测试使用隔离目录和模拟飞书；真实飞书定时执行、确认卡及文档联动仍待验收。

## 1. 产品结论

两个入口、同一套任务管理：

- 软件首页增加「定时任务」，统一查看、创建、暂停和管理本机所有 Agent 的计划。
- 群里真实 @机器人，用自然语言描述时间和工作，机器人生成待确认卡片；确认后才能成为生效计划。
- Agent 详情和群设置只放筛选后的入口与数量，不重复出现一整套配置或授权卡。
- 单 Agent 执行与组织者自动协调共用计划系统。调度器只负责到点触发，沿用现有执行权限、工作空间和协作流程。
- 人协调的业务表格仍保留；计划不会擅自建立或改写正式表格。

默认使用已有工作台的白底、蓝色主按钮、圆角卡片、头像和状态标签。高级选项折叠；不让普通用户输入 cron。

## 2. 核心概念：计划与执行分开

| 对象 | 示例 | 生命周期 |
| --- | --- | --- |
| 定时计划 SCH-xxxx | 每个工作日 09:00 检查需求 | 持续存在，可编辑、暂停、恢复、删除 |
| 本次执行 RUN-xxxx | 9 月 22 日 09:00 的检查 | 独立运行、完成、失败、等待人工或取消 |
| 协作任务 TEAM-xxxx | 本次检查需研发、测试配合 | 每次协调执行产生新的 TEAM 编号，不复用昨天的任务 |
| 任务文档 | 需求检查 · 2026-09-22 09:00 | 每次实际执行独立创建，关联计划及 RUN/TEAM 编号 |

计划详情是跨日期索引；任务文档是单次过程记录。不能每天覆盖同一份过程文档，也不能继承上一次任务的执行授权或模型会话。

## 3. 软件创建流程

首页「定时任务」→「新建定时任务」→填表→查看时间和行为摘要→「创建并启用」。

### 表单

| 字段 | 默认与交互 |
| --- | --- |
| 名称 | 从任务内容生成，可修改，例如「工作日需求检查」 |
| 执行 Agent | 从已绑定机器人选择；从 Agent 详情进入则预填 |
| 目标群／项目 | 只选当前 Agent 已启用的群；显示项目名与绑定工作目录 |
| 执行方式 | 单 Agent／组织者协调；后一项仅对开启协调模式的群可选 |
| 做什么 | 任务目标、完成标准、限制、资料链接；文本输入 |
| 执行时间 | 一次、每天、每周、周一至周五；一次需日期和时刻 |
| 时区 | 默认当前设备时区，显示「北京时间 Asia/Shanghai」等明确标签 |
| 结果发送到 | 第一版固定所选群，可选择「仅记录、不发群消息」 |
| 行为范围 | 默认「只读并汇总」；要修改资料需显式说明对象和允许操作 |

摘要必须显示：所选 Agent、群、工作内容、行为范围、时区、未来三次执行时间、是否发送群消息、运行设备。

时间无效、群未启用、Agent 不存在或执行方式不匹配时，原位说明并阻止启用。机器人离线可保存为草稿，启动并检查后再启用。

只对缺少的实际权限提示补充，复用已有授权。应用权限正常不等于文档已分享给机器人，仍需验证所选资料可读。无法验证时标为「待检查」，不能显示全部就绪。

高级选项：超时上限、错过执行策略（第一版固定跳过，展示说明）、结果通知。第一版不提供任意脚本、秒级频率、无限重试。

## 4. 群聊创建流程

用户示例：

> @组织者 每个工作日早上 9 点，检查需求表里还没完成的需求，在本群汇总，只读不要修改。

机器人返回确认卡片：

- 标题：创建定时任务 · 工作日需求检查
- 执行者：组织者；方式：自动协调
- 时间：周一至周五 09:00，北京时间
- 下次执行：完整年月日和星期（由系统实际计算）
- 内容：读取已绑定需求表，汇总未完成需求，不改表、不上线
- 结果：发送到本群；每次执行创建独立任务文档
- 运行条件：本机软件后台运行、电脑联网且未休眠
- 按钮：「确认创建」「修改」「取消」

保存成功后返回 SCH 编号、实际 nextRunAt 和「查看计划／暂停」入口。不能在持久化成功前说「已经安排好了」。确认卡过期则重新预览，不创建计划。

规则：

1. 缺少时刻、时区含糊或任务不明确，只追问缺项，不猜时间。
2. 「工作日」第一版解释为周一至周五，明确不含法定节假日和调休判断。
3. 创建定时计划不等于立即执行。需要现在运行时单独点「立即运行一次」。
4. 重复点击同一卡片，只创建一个计划。重新发同样要求时展示已有计划，允许用户明确另建，不静默重复。
5. 仅机器人拥有者／配置管理员能确认长期计划。普通成员可得到权限说明，不能借群聊获得本机长期执行权。
6. 卡片点击校验真实操作者、计划归属、群、草稿版本和有效期；机器人消息不能创建或确认计划。
7. 旧版客户端不支持时明确说明，绝不能仅让模型回复「好的，每天执行」。

## 5. 计划列表与详情

### 列表

顶部：标题、运行设备、软件运行说明、「新建定时任务」。

筛选：全部／已启用／已暂停／需要处理；可按 Agent、群筛选。

每行展示：名称、Agent 和群、时间规则、计划状态、下次执行、最近结果。

主操作：查看记录；更多菜单：立即运行一次、编辑、暂停／恢复、删除。

将「计划已启用」与「当前正在执行」分开显示，不能用同一个绿色在线标签代替两者。

空状态：说明用途并给出两个示例——每天整理群待办、每周检查项目需求。点击示例只预填创建表单，不直接启用。

### 详情

- 基本信息：计划规则、任务内容、执行者、群、权限范围、设备、创建人、最近修改时间。
- 下次执行：准确日期时刻、时区与可运行条件。
- 执行记录：计划时间、实际开始时间、耗时、状态、结果摘要、任务文档、关联 TEAM。
- 每条记录展开显示：触发来源、步骤进度、人工反馈、失败原因、通知发送状态。
- 「等待人工」时突出显示需要谁补充什么，提供文档与回到群的入口。

## 6. 每次运行与任务文档

调度到点 → 写入本次执行记录 → 检查运行条件与权限 → 创建并分享本次文档 → 启动 Agent／新 TEAM → 同步阶段记录 → 发布结果摘要和文档链接。

文档格式沿用任务文档，顶部是最新状态，下面保留过程：

1. 标识：名称、SCH/RUN/TEAM 编号、计划时间、实际时间、群／项目。
2. 目标、资料、完成标准与允许操作。
3. 当前进度、负责人、下一步。
4. 时间线：开始、派单、回执、阻塞、人工补充、恢复、取消、完成。
5. 最终结果、证据与未完成项。

单 Agent 也使用同一套文档服务，不为它伪造团队派单。组织者模式复用本次 TEAM 文档，不额外建第二份。未真正开始的「错过／跳过」只保留执行记录，避免产生空文档。

仅记录任务级过程；不承诺上传完整工具日志或本机截图。发起人可编辑、目标群可查看，不公开分享。通过 @提交的反馈进入本次文档；手工改文档不自动变成执行指令。

## 7. 暂停、取消和删除

| 操作 | 影响 |
| --- | --- |
| 暂停计划 | 停止未来触发；已经开始的本次运行继续 |
| 恢复计划 | 从下一次将来的计划时间开始，不补跑暂停期间的历史 |
| 取消本次执行 | 请求停止当前运行，并停止后续协调；收到停止确认前显示「正在取消」 |
| `/team cancel` | 沿用现有语义：只取消本次协调，不强停执行者；不删除定时计划 |
| 删除计划 | 停止未来触发并归档计划；保留执行历史和任务文档；不删除外部文件 |
| 立即运行一次 | 使用当前已保存版本，生成独立 RUN；不移动下次定时触发时间 |

UI 删除说明应明确「保留历史；当前运行不受影响」。编辑只影响未来触发，当前运行继续使用开始时保存的计划快照。

建议新增命令（待实现）：

- `/schedule list`：列出本群可管理的计划。
- `/schedule show SCH编号`：查看规则、下次执行与最近结果。
- `/schedule pause SCH编号`、`/schedule resume SCH编号`。
- `/schedule run SCH编号`：立即运行一次，需要防重复确认或等价的明确指令。
- `/schedule delete SCH编号`：返回删除确认卡。
- `/schedule help`：帮助。

不占用 `/team`，不把普通自然语言「继续」同时解释为恢复计划和恢复本次任务。

## 8. 离线、失败与并发规则

- 软件在 macOS 菜单栏后台运行时可以调度；完全退出、关机、休眠时无法执行。首版不承诺唤醒电脑或云端代跑。
- 重启后恢复计划。错过的周期执行默认跳过并记录，不连续补跑；一次性任务过期标「已错过」，由人决定补跑。
- 断网、机器人离线、资料权限失效时记录明确原因，不无限等待、不假装完成。
- 同一计划最多一条活跃运行。到点仍未结束时记录「跳过：上次尚未结束」。
- 组织者所在会话已有其他 TEAM 时，不接管或取消它；本次记录「跳过：该群正在协作」。首版不增加隐式长队列。
- 需要人工补充时保留本次文档并真正 @计划创建人；自动暂停该计划以防每天堆积待补充任务。人工处理本次后，需明确恢复计划。
- Agent 已产生外部操作但进程中断时，标「结果待核对」，不自动重跑。
- 群消息投递失败不重跑业务任务。分开记录执行结果和通知结果，仅重试未确认的通知，并避免重复发送。
- 第一版失败不自动重试整个任务；用户看完错误后手动重试，创建新 RUN 并关联原记录。
- 多台机器第一版各自拥有本机计划，不复制启用状态。导入计划默认为暂停；没有分布式锁时不得宣称跨机器只执行一次。
- 时区固定保存。改电脑时区不改变既有计划。夏令时不存在的时刻跳过；重复时刻只触发一次，并在未来时间预览中体现。

## 9. 技术落地建议

建议新增 `src/schedule/`，复用现有 supervisor、run-flow、权限检查、持久化锁和任务文档服务，不另起一套 shell cron：

- `store.ts`：计划、执行记录和版本快照，原子写入与进程锁。
- `next-run.ts`：受限时间规则、时区和下一次触发计算。
- `scheduler.ts`：启动恢复、计时、唤醒后核对、并发去重和触发领取。
- `runner.ts`：通过现有执行管线提交；组织者运行创建新 TEAM。
- `commands.ts`：群聊草稿、确认卡、权限及幂等操作。
- `api.ts`：工作台列表、创建、编辑、暂停、恢复与记录查询。
- 前端 `ScheduledTasks` 列表、`ScheduleEditor` 表单、`ScheduleRuns` 详情。

计划数据：id、revision、profile、chatId/threadId、project、mode、prompt、allowedActions、creator、timeZone、rule、nextRunAt、enabled、notificationTarget、createdAt、updatedAt。

执行数据：runId、scheduleId、scheduleRevision、scheduledFor、trigger、attemptOf、dedupeKey、status、startedAt/endedAt、taskId、documentUrl、result、error、deliveryStatus。每次保存不可变的任务／权限快照，审计实际按什么要求运行。

去重键采用计划 ID + 计划版本 + 当次计划时刻；先持久化领取记录，再启动执行。崩溃后将未完成领取标为待核对，不声称对任意外部副作用都可做到严格 exactly-once。

现有 `task-document.ts` 面向 TEAM，需要提取共享文档适配层支持单 Agent。现有 `/team cancel` 不强停执行者，新增「取消本次执行」必须联动执行句柄并核实结果，不能只改状态字。

首次启用保存的是指定任务与通知范围，不是永久开放任意读写。每次执行重新检查用户、机器人、群和资源权限；改计划的群、执行者或行为范围需重新确认。敏感凭据不写入计划和文档。

## 10. 首版验收标准

1. 页面创建与群卡创建落在同一计划列表，可双向暂停和查看状态。
2. 点击确认两次只生成一个计划，重启后计划保留。
3. 到点只生成一条 RUN，组织者模式只生成一个 TEAM 和一份文档。
4. 第二天生成新文档、新会话；不带入前一天的临时指令和未授权操作。
5. 暂停后不触发；恢复后不补历史；编辑不改变已运行快照。
6. 验证退出、睡眠后恢复、断网、权限失效、机器人被手动停止的提示。
7. 验证重叠任务、同群已有 TEAM、进程中断及发送结果不确定时不会重复执行。
8. 等待人工时通知正确的人、暂停未来触发；反馈只续接对应任务。
9. 普通群成员、其他机器人、过期卡片和跨群回调不能启用或修改计划。
10. 用真实飞书群跑一次单 Agent和一次组织者任务，核对文档、群结果和工作台记录，再标记功能可用。

首版之外：云端常驻、电脑自动唤醒、跨机器接管、法定节假日、任意 cron、表格事件触发和失败自动重跑。
