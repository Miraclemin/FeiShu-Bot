# 巡检模式

> 先遵守 [配置与身份约定](context.md)。软件群任务使用注入配置和当前机器人；本页固定脚本、路径、群/表及身份仅是旧流程示例。只读查询不执行写入或调度流程。

执行最新规则 `<TOOLS_ROOT>/inspector/DIRECTIONS.md`，其中旧的“尚无Skill转表执行入口”描述由本Skill的promotion.md替代；无常驻监听、无按钮自动触发的限制仍有效。

工具工作目录 `<TOOLS_ROOT>`。
- `python3 inspector/round_guard.py acquire <唯一批次>` / `finish <同批次>`：整轮占用；未知旧任务不得抢占。
- `python3 inspector/explore.py plan`：实际读取方向和历史日志；将输出存到本批次证据目录。
- `python3 inspector/explore.py start --input <JSON>`：写开始与选择理由。
- `python3 inspector/explore.py finish --input <JSON>`：写实际结果与未测项，重算次数。
- `python3 inspector/publish.py <问题JSON>`：只写疑似缺陷。群内以bot身份执行时添加 --bot-table。

输入结构与界限从DIRECTIONS.md读取；Skill不复制维护第二套。不要运行setup/seed/历史迁移脚本。
脚本必须有实际调用结果。浏览器工具不可用、登录或权限受阻时写清原因。允许收费AI测试、有权限的跨用户会话检查和代码修复；禁止删除已有数据，上线另行确认。执行前必须读取permissions-login.md并完成登录预检。

## 持久轮转（最新规则）
plan返回queue，由主Agent按pending顺序reserve整批方向；不能总挑前三个。round为覆盖轮次，pending是本轮未完成、且本巡检夜尚未执行的方向；deferred_until_next_night是今晚已执行但未完成的方向。新启用方向补入本轮剩余队列，既有队列不因优先级反复变化而打乱；优先级决定首次入队及下一轮先后，不允许跳过其余方向重查前面的方向。
每个方向本轮先完成一个具体场景，下一覆盖轮再深入新场景。plan推进轮次仅发生在全部开启方向已通过/发现问题/明确受阻、且当前开启方向本巡检夜均未执行过时，避免同一晚完成后开启下一轮重查。受阻只是尝试过，不算覆盖成功，群报告分开统计。中断为待继续，下一次重新核查安全恢复条件，沿用场景设计，新日志需写明续接；同一方向执行中未知状态不能重复领取。
finish返回本轮queue；night_complete=true或round_attempted=true时，应发摘要并结束本次执行，不立刻plan开始无限下一轮。每个子Agent各有20分钟预算，由主Agent监控截止时间并中断超时执行；整轮不是共用20分钟。未知工具状态先核查，不能假装已停止。
plan/sync会写回方向表：当前覆盖轮次、本轮进度、排队顺序。排队顺序1表示下一优先处理项；空白表示今晚已执行、正在执行或当前未开启；超时项仍显示“待继续”，查看下次探索建议了解续查位置，不代表永久完成。全部关闭继续自主模式，日志覆盖轮次为空，不冒充完成指定方向一轮。
旧日志没有覆盖轮次，只计历史总次数，不补填新轮次。轮转状态保存在工具目录artifacts/coverage-state.json，禁止删除重置；异常先核对日志。场景键保持稳定，覆盖场景数不因重复运行增加。


## 子Agent分批并行（当前执行方式）
用户授权调用子Agent并行巡检。主Agent只负责分配、串行写表、计时、去重、汇总；子Agent探索各自方向，不直接并发调用写表脚本。
并发上限为5个巡检子Agent（不含主Agent），实际数量=min(5,当前可用子Agent槽位,剩余方向数)。必须读取当前工具提供的容量和已运行Agent，不假定总槽位为5。当前环境总4槽，主Agent占1，最多3个巡检子Agent，不绕过限制。

1. 主Agent取得整轮锁，plan读取方向。准备reserve JSON：`{"batch":"日期-wave-01","available_child_slots":3}`；自主模式首次reserve必须提供今晚完整的direction_ids（最多5个，并非本批的3个），之后各批省略direction_ids，脚本复用锁定清单。运行 `python3 inspector/explore.py reserve --input 文件`，返回本批次固定assignments。不得在已有未结束批次上重复reserve。
2. 主Agent按assignments逐项start登记，立即spawn对应子Agent；任务中带唯一方向record_id、探索日志record_id、明确场景、真实项目目录、独立浏览器标签页及测试数据前缀、开始时间和deadline。启动前读取该方向最新开关；若关闭或spawn失败，登记本项受阻/中断，不把预留项无声丢弃。
3. 子Agent在自己的标签页上探索，禁止操作其他子Agent的标签页；即使独立标签也共用账号。只读任务可同时跑；写同一数据的场景由主Agent避免冲突，不能依赖标签隔离账号状态。浏览器工具无法提供可独立控制的页面时记录受阻，不用多个Agent抢同一窗口。
4. 子Agent输出实际步骤、预期/实际、截图路径、异常复现、未测项与下一步，并报告结束。不写正式Bug、不直接发群摘要、不自行开更多子Agent。
5. 主Agent用可用agent状态与消息工具监控，每次等待不超过60秒。每个子Agent从start记录计20分钟，到deadline调用interrupt_agent，核查它已停止或仍有工具在途。已安全结束才finish为中断，保留已做部分；超时不算通过。挂起工具未证实停止则保留占用并提示，不开下一批。这是主Agent执行的超时管理，不是后台系统硬杀保证。
6. 任一子Agent先完成，主Agent立即串行finish写进度，但**不补进下一方向**。本批所有子Agent结束、工具状态确定后才能reserve下一批。每个方向不重复领取；本轮五个方向若容量3，则先ABC，全部结束再DE。
7. 一轮覆盖完成后汇总一次群报告；表格可以同时有多个检查中。中断项记录待继续，不立即在同一轮反复重试到无穷；先继续后续未执行方向；当晚pending为空才结束本次执行，下一个巡检夜从未完成项继续。整轮锁保留到所有子Agent停止。

批次状态在artifacts/inspection-wave.json；日志和分配记录是恢复依据。没有日志的预留项不能被直接覆盖，主Agent需核对是否曾启动并记录未执行原因，再安全结束该批。

尚未start的预留项因关闭方向或无槽位而不能启动时，主Agent确认未启动任何子Agent后使用cancel-reservation，输入batch、direction_id、reason；已有关联日志的项目只能finish，不能取消预留来掩盖未完成。

## 同一晚最多一次（代码强制）
北京时间22:00至次日22:00为一个巡检夜，跨零点不重置。coverage.schedule从持久探索日志的开始时间和关联方向恢复attempted_tonight，不依赖当前聊天记忆或最新一批的文件。已启动的通过、发现问题、受阻、中断均占用本夜一次；计划中和历史补录不占用。缺失或无法解析开始时间时停止并核对，不猜测可重跑。
reserve和start另有同夜拦截；改变批次名、覆盖轮次、开关或进入自主模式都不允许自动重查已执行方向。start返回already_started时仅恢复核对该日志和原Agent，不重新spawn。未启动且安全取消的预留项不计执行。
reserve返回night_complete=true且assignments为空时，不再spawn或反复reserve；发本次摘要。有待继续项时明确说“已查X个方向，其中Y个未完成，保留进度下晚继续”，不称全部检查完成。20分钟超时仍须先确认Agent及工具已停止，再finish中断。
用户明确要求白天继续指定方向时属于额外手动执行意图；当前这些自动调度命令仍会拦截同夜重复，不能删除日志或换批次绕过，也不要承诺现有命令可直接重跑。

## 自主探索固定清单
每个巡检夜先结合网站入口、历史覆盖和未测项，选定最多5个方向；可以少于5个，不凑数。先确定全部候选再登记必要的新方向，已有方向复用，不为同一方向换名建行。首次reserve将完整清单锁定到artifacts/autonomous-<巡检夜>.json，之后不能追加、替换、缩减或删除该文件重置；更换批次或重启仍复用它。
实际槽位3且清单5项时，先3项，整批结束再剩余2项；每项20分钟，超时不在当晚重试。清单已无可执行项时汇总并结束，不再生成新方向或新一轮。中途发现值得进一步检查的新方向，只记录在日志的下次建议，留到下一巡检夜选题，不在当晚继续新增方向行、扩大清单。取消且未启动的项记录原因，本夜跳过，不用新方向补位。
没有合适方向时允许首次传空清单，说明原因后结束。此5项限制只约束自主探索，人工开启20项时仍按既有分批规则覆盖20项。人工改变开关导致模式变化时先结束或取消原批预留，再按实时模式规划，不用模式切换绕过已锁定的自主清单。
